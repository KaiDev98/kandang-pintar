# Bagian A. Desain UI/UX

## 1. Prinsip Desain

1. **Cepat sebelum cantik.** Pencatatan harian di bawah 30 detik. Setiap layar dinilai dari jumlah ketukan.
2. **Terbaca di bawah matahari.** Kontras tinggi, huruf besar, status memakai warna, ikon, dan teks sekaligus.
3. **Satu tangan, satu ibu jari.** Semua aksi utama ada di separuh bawah layar.
4. **Memandu, bukan hanya menyimpan.** Layar kosong selalu menawarkan langkah berikutnya; angka penting selalu disertai artinya.
5. **Jujur soal ketidakpastian.** Angka perkiraan (FCR umbaran, prediksi panen, laba sementara) diberi label "perkiraan".
6. **Bahasa peternak, bukan bahasa sistem.** "Efisiensi pakan", bukan "FCR". "Ayam hilang", bukan "mortality adjustment".

## 2. Arah Visual

**Subjek:** peternakan ayam kampung skala kecil di Indonesia, dipakai pemula di luar ruangan.
**Satu hal yang diingat:** tombol **Catat** berwarna kuning dedak yang selalu ada di tengah navigasi bawah, dan **Jejak 7 Hari** di Beranda (tujuh titik yang terisi tiap hari ada catatan). Kebiasaan mencatat adalah KPI utama produk, jadi itulah yang dibuat menonjol. Elemen lain sengaja tenang.

**Yang dihindari dengan sengaja:**

- Latar krem dengan aksen terakota (terlalu umum dan tidak membantu keterbacaan di bawah matahari).
- Deretan kartu identik dengan bayangan lembut yang sama.
- Label huruf kapital berjarak lebar di atas setiap judul.
- Satu kata beraksen warna di tengah judul.

**Suara:** hangat, singkat, kalimat aktif, huruf sentence case.

### 3.3 Tipografi

Satu keluarga huruf: **Atkinson Hyperlegible Next** (dirancang untuk keterbacaan; dipilih karena dipakai di luar ruangan oleh pengguna awam). Di-host sendiri lewat `next/font` agar tidak ada permintaan eksternal dan tetap tersedia offline. Angka memakai `font-variant-numeric: tabular-nums` supaya kolom Rupiah rata.

| Peran | Ukuran / tinggi baris | Bobot |
| --- | --- | --- |
| Angka besar (HPP, laba) | 32 / 36 | 800 |
| Judul layar | 24 / 30 | 800 |
| Judul bagian | 18 / 24 | 600 |
| Isi | 16 / 24 | 400 |
| Label dan keterangan | 14 / 20 | 600 / 400 |

Ukuran isi minimum 16 px (mencegah zoom otomatis di input dan menjaga keterbacaan). Panjang baris isi di bawah 70 karakter. Tidak memakai huruf kapital semua untuk label.

### 3.4 Jarak, sudut, dan bayangan

- Skala jarak 4 px: 4, 8, 12, 16, 24, 32.
- Margin halaman 16 px; jarak antar bagian 24 px.
- Sudut mengikuti hierarki: kartu 16 px, input dan tombol 12 px, chip 999 px, bottom sheet 24 px (sudut atas), tombol Catat berbentuk pil.
- Pemisah memakai garis 1 px `--line`, bukan bayangan. Bayangan hanya untuk elemen melayang (bottom sheet, tombol Catat, toast).

### 3.5 Gerak

- Gerak hanya sebagai respons aksi: angka stepper berganti, centang tersimpan, titik Jejak 7 Hari terisi setelah Simpan.
- Durasi 120–200 ms. Hormati `prefers-reduced-motion` (ganti dengan perubahan instan).
- Tanpa animasi masuk otomatis pada bagian halaman.
- Getar singkat (haptic) saat Simpan berhasil, bila perangkat mendukung.

## 4. Layout dan Navigasi

- Desain dimulai dari lebar **360 px**. Desktop adalah perluasan: konten dibatasi lebar maksimum 720 px di tengah, navigasi bawah berubah menjadi rel samping di atas 1024 px.
- **Navigasi bawah, lima tab:** Beranda · Ayam · **Catat** (tengah, menonjol) · Keuangan · Asisten. Tab Catat berbentuk pil kuning yang sedikit naik dari bilah.
- Hormati area aman (`env(safe-area-inset-bottom)`) dan tinggi bilah navigasi 64 px.
- Pengaturan, Notifikasi, dan Ekspor diakses dari ikon di pojok kanan atas Beranda dan dari menu profil, bukan dari tab.
- Navigasi kembali: tombol kembali di kiri atas pada layar anak; layar form penting memakai bottom sheet agar konteks tidak hilang.

```
┌────────────────────────┐
│ Judul layar     🔔  ⚙  │  ← bilah atas 56 px
├────────────────────────┤
│                        │
│   konten (scroll)      │
│                        │
├────────────────────────┤
│ 🏠   🐔   [ Catat ]  💰  💬 │  ← navigasi bawah 64 px
└────────────────────────┘
```

## 6. Spesifikasi Layar

### 6.1 Beranda (FR-DSH-01)

Pertanyaan utama yang dijawab: *"Hari ini perlu apa, dan usahaku untung atau rugi?"*

```
┌────────────────────────────────┐
│ Selamat pagi, Pak          🔔 ⚙│
│ ┌────────────────────────────┐ │
│ │ Hari ini belum dicatat     │ │
│ │ ● ● ● ● ○ ◉ ·   Jejak 7 hari│ │
│ │ [  Catat sekarang  ]       │ │
│ └────────────────────────────┘ │
│ Perlu perhatian (2)            │
│  ▲ Vaksin Batch A jatuh tempo  │
│  ! Hitung ulang umbaran Batch B│
│ Ayam                           │
│  ┌ Batch A ✓ Aman ───────────┐ │
│  │ 18 ekor · umur 72 hari    │ │
│  │ ▓▓▓▓▓▓▓░░ 14 hari lagi    │ │
│  └───────────────────────────┘ │
│  ┌ Batch B ! Perhatian ──────┐ │
│  └───────────────────────────┘ │
│ Hari ini: Pakan 1,2 kg · Rp 6.000│
│ Telur 2 · Air sudah diganti ✓  │
│ Bulan ini                      │
│  Biaya Rp 215.000              │
│  Proyeksi laba (perkiraan)     │
│  Rp 480.000                    │
└────────────────────────────────┘
```

Urutan konten: kartu kebiasaan (bagian paling atas) → peringatan → batch → ringkasan hari ini → ringkasan bulan ini. Kartu kebiasaan berubah menjadi "Catatan hari ini lengkap ✓" setelah Simpan. Mortalitas dan status kesehatan tampil di dalam kartu batch.

### 6.2 Catat Cepat (FR-FED, FR-WTR, FR-EGG, FR-FLK-04)

Satu layar penuh dengan semua catatan harian. Target: di bawah 30 detik.

```
┌────────────────────────────────┐
│ ← Catat hari ini     Sel, 27 Okt│
│ Untuk siapa?                   │
│ [Batch A] [Batch B] [Indukan]  │
│ Pakan                          │
│  Pur      [−]  0,6 kg  [+]     │
│           Rp 6.000 (otomatis)  │
│  Dedak    [−]  0,6 kg  [+]     │
│           Rp 0                 │
│  + Benih beras (opsional)      │
│ Minum                          │
│  ☑ Air sudah diganti & wadah   │
│    dibersihkan                 │
│  Isi liter & vitamin ›         │
│ Telur (per induk)              │
│  Betina 1 [−] 1 [+]            │
│  Betina 2 [−] 0 [+]            │
│ Ayam mati   [−] 0 [+]          │
│                                │
│ [ Simpan catatan hari ini ]    │  ← tombol menempel di bawah
└────────────────────────────────┘
```

Aturan perilaku:

- Pemilih "Untuk siapa?" memilih batch atau indukan; bagian Telur hanya muncul pada Indukan, bagian Ayam mati hanya pada Batch.
- Nilai awal diambil dari catatan hari sebelumnya. Harga pur otomatis = berat × harga default; dapat diketuk untuk mengubah.
- Bila ayam mati > 0, muncul pilihan cepat dugaan penyebab (opsional, dapat dilewati).
- Setelah Simpan: toast "Tersimpan" + titik Jejak 7 Hari terisi + haptic. Saat offline: "Tersimpan di HP, akan dikirim saat online".
- Keluar dari layar yang belum disimpan memunculkan konfirmasi; draf otomatis tersimpan lokal.

### 6.3 Ayam (FR-FLK, FR-EGG)

Daftar batch dengan filter Aktif, Siap jual, Selesai. Di atas daftar ada dua pintasan: **Kalender siklus** dan **Indukan dan kandang**.

**Detail batch** (tab di dalam layar):

| Tab | Isi |
| --- | --- |
| Ringkasan | Populasi, umur, fase (kandang/umbaran), progres panen, status kesehatan, tombol aksi (Pindah ke umbaran, Hitung ulang, Catat mati, Tutup batch) |
| Pertumbuhan | Kurva bobot vs ambang 1 kg, tombol Timbang sampel (FR-GRW) |
| Pakan | Riwayat dan total biaya pakan, biaya per ekor per hari, efisiensi pakan (perkiraan) |
| Kesehatan | Catatan gejala, vaksin, status |
| Biaya dan laba | HPP per ekor, laba sementara, rincian biaya (FR-SAL-06) |

**Indukan dan kandang:** kartu per kandang (terisi atau kosong, jumlah ayam/25, induk dan batch di dalamnya) dan kartu per tempat pengeraman (bebas atau dipakai Betina X sampai tanggal Y).

**Alur Mulai Pengeraman:** sheet berisi induk (hanya yang bebas), tempat pengeraman (hanya yang bebas), tanggal mulai, jumlah telur; di bawah muncul perkiraan menetas. Bila ada konflik, pesan: "Tempat 1 sedang dipakai Betina 2 sampai 12 Nov. Pilih tempat lain atau tunggu sampai selesai."

**Alur Hasil Tetas:** sheet berisi jumlah menetas → menampilkan hatch rate, pembanding target (> 10 anakan), kandang tujuan → batch baru dibuat.

**Alur Hitung Ulang (umbaran):** satu kolom angka "Berapa ekor yang ditemukan?" dengan catatan sistem di bawahnya "Tercatat 17 ekor". Bila beda, muncul pilihan: hilang atau mati.

**Kalender siklus:** garis waktu horizontal per kandang dan per tempat pengeraman, memuat mulai eram, menetas, umbaran, perkiraan panen.

### 6.4 Keuangan (FR-CST, FR-SAL)

Tab internal: **Ringkasan · Penjualan · Biaya · Laba**.

- **Ringkasan:** pemasukan dan pengeluaran bulan ini, arus kas, daftar piutang.
- **Penjualan:** daftar transaksi; tombol "Jual ayam".
- **Biaya:** daftar per kategori dan komposisi (donat), tombol "Tambah biaya" (kategori, jumlah, batch atau umum, foto nota).
- **Laba:** pilih batch; angka besar HPP per ekor, laba sementara atau final, margin, ROI; kalkulator harga (harga impas dan harga disarankan); perbandingan antarbatch.

**Alur Jual ayam (3 langkah):**

1. Pilih ayam: daftar batch dengan jumlah yang layak jual (umur dan bobot rata-rata). Jumlah ekor per batch lewat stepper.
2. Per ekor: bobot dan harga (default Rp 70.000), checklist sehat ringkas. Ayam di bawah ambang diberi tanda dan butuh konfirmasi "Tetap jual".
3. Tinjau: pembeli (opsional), ongkos kirim, status bayar, tampilan ringkasan laba. Tombol "Simpan penjualan".

Angka laba ditandai "sementara" selama batch belum ditutup.

### 6.5 Asisten AI (FR-AI)

Layar percakapan dengan dua mode di bawah kolom input: **Catat** dan **Tanya**.

- Mode Catat: pengguna mengetik "tadi pagi kasih pur 1 kg, 1 ekor mati". Aplikasi menampilkan **kartu pratinjau** berisi data terstruktur ("Pakan: pur 1 kg · Rp 10.000. Ayam mati: 1") dengan tombol **Simpan** dan **Ubah**. Tidak ada yang tersimpan sebelum Simpan ditekan.
- Mode Tanya: jawaban berisi angka dari data peternakan, disertai tautan ke layar sumbernya.
- Cek kesehatan awal: formulir gejala dan foto; hasil berupa chip urgensi dan langkah awal, dengan disclaimer permanen. Gejala berbahaya menampilkan kartu merah berisi arahan menghubungi dokter hewan atau dinas peternakan.
- Bila AI tidak tersedia: pesan "Asisten sedang tidak bisa dipakai. Pencatatan biasa tetap berjalan" dengan tombol ke Catat Cepat.

### 6.6 Notifikasi, Ekspor, Pengaturan

- **Notifikasi:** daftar alert diurutkan menurut tingkat (Tindakan, Perhatian, Info), tiap item punya tombol aksi langsung ("Catat vaksin", "Hitung ulang").
- **Ekspor:** dua kartu, **Laporan per batch** dan **Seluruh catatan harian**; pilihan format .xlsx atau .csv.
- **Pengaturan:** kandang, parameter (ambang layak jual, lama pengeraman, batas kandang kosong, harga pur, harga acuan), mode tampilan, mode demo.

### 6.7 Onboarding dan Mode Demo

- Wizard tiga langkah dengan bilah progres: (1) Buat kandang, (2) Daftarkan indukan, (3) Catat pakan pertama. Setiap langkah punya tombol "Lewati dulu".
- Tombol **Coba dengan data contoh** di layar pertama. Mode demo ditandai pita tetap "Data contoh" di bilah atas; tombol "Hapus data contoh" satu ketukan dengan konfirmasi.

## 7. Pola UX

| Situasi | Pola |
| --- | --- |
| Memuat data | Skeleton sesuai bentuk konten, bukan spinner layar penuh |
| Simpan | Optimistic UI: tampilan berubah langsung, sinkron di latar belakang; bila gagal, item ditandai dan dapat dicoba ulang |
| Error | Jelaskan masalah dan cara memperbaiki dalam satu kalimat, tanpa kode teknis ("Berat pakan belum diisi. Isi angka lebih dari 0.") |
| Hapus | Soft delete dengan Urungkan 5 detik; hapus data keuangan butuh konfirmasi eksplisit |
| Offline | Banner jelas, penghitung catatan menunggu, aksi yang butuh internet dinonaktifkan dengan penjelasan ("Jual ayam perlu internet") |
| Konflik aturan bisnis | Pesan menyebut aturan dan jalan keluarnya (contoh di 6.3) |
| Angka perkiraan | Label "perkiraan" atau "perkiraan awal" dan penjelasan singkat saat diketuk |
| Status | Warna + ikon + teks pada semua tempat |
| Konfirmasi AI | Selalu lewat kartu pratinjau; tombol Simpan dan Ubah sama-sama terlihat |

## 8. Kamus Bahasa (microcopy)

| Hindari | Pakai |
| --- | --- |
| FCR | Efisiensi pakan (keterangan: "berapa kg pakan untuk tambah 1 kg bobot") |
| HPP | Modal per ekor (HPP) |
| Break-even | Harga impas |
| Mortalitas | Ayam mati (%) |
| Culling / afkir | Disisihkan |
| Hatch rate | Persen menetas |
| Submit | Simpan catatan hari ini |
| Sync | Kirim ke server / Terkirim |
| Error 500 | Gagal menyimpan. Coba lagi |

Aksi dan hasilnya memakai kata yang sama: tombol "Simpan penjualan" menghasilkan toast "Penjualan tersimpan".

## 9. Aksesibilitas

- Target sentuh ≥ 44 px (stepper 56 px), jarak antar target ≥ 8 px.
- Kontras teks ≥ 4,5:1, komponen UI ≥ 3:1.
- Fokus keyboard terlihat (cincin 3 px Daun), urutan fokus logis, semua kontrol berlabel.
- Ukuran huruf mengikuti pengaturan sistem; layout tidak rusak pada pembesaran 200%.
- Status tidak mengandalkan warna saja.
- Grafik memiliki ringkasan teks sebagai alternatif.
- `prefers-reduced-motion` dihormati.

# Bagian B. Desain Teknis

## 10. Arsitektur dan Struktur Proyek

Monolit modular Next.js (App Router), satu codebase untuk UI dan server.

```
┌──────────── Klien (PWA, Chrome Android) ────────────┐
│ UI (React + Tailwind) · TanStack Query · IndexedDB  │
│ Service worker (Serwist): cache aset, antrean sync  │
└───────────────────────┬──────────────────────────────┘
                        │ HTTPS (Cloudflare)
┌───────────────────────▼──────────────────────────────┐
│ Next.js: Server Components · Server Actions ·         │
│ Route Handlers (/api/sync, /api/export, /api/ai/*)    │
│ ┌──────────────── Modul domain ───────────────────┐  │
│ │ flock · hatchery · feed · health · finance ·    │  │
│ │ monitoring · ai                                  │  │
│ └──────────────────────────────────────────────────┘  │
│ pg-boss worker (proses terpisah): alert, pengingat    │
└───────┬──────────────────┬──────────────────┬─────────┘
        │                  │                  │
   PostgreSQL        Object storage       LLM API
   (data + pg-boss)  (foto, backup)       (lewat abstraksi)
```

**Struktur folder:**

```
src/
  app/                      # rute (beranda, catat, ayam, keuangan, asisten, ...)
  modules/
    flock/    { service.ts, repo.ts, schema.ts, rules.ts }
    hatchery/ feed/ health/ finance/ monitoring/ ai/
  db/         { schema/, migrations/, client.ts }
  lib/        { money.ts, dates.ts, idempotency.ts, auth.ts }
  pwa/        { sw.ts, queue.ts, sync.ts }
  workers/    { index.ts, jobs/ }
  components/ ui/ (shadcn)  domain/
tests/        unit/ integration/ e2e/ ai-eval/
```

**Aturan modul:**

- Modul hanya mengakses tabel miliknya sendiri; komunikasi lewat service modul lain.
- Skema Zod dibagi antara klien dan server (`modules/*/schema.ts`).
- Logika bisnis (HPP, alokasi, aturan kandang) hanya ada di `service.ts` dan `rules.ts`, murni dan mudah diuji. Komponen UI tidak menghitung uang.

## 11. Desain Data (PostgreSQL)

### 11.1 Konvensi

- Primary key `uuid` (UUIDv7 bila tersedia).
- Setiap tabel domain punya `farm_id`, `created_at`, `updated_at`, dan `deleted_at` bila perlu soft delete.
- Uang: `bigint` dalam Rupiah. Berat: `integer` dalam gram. Waktu: `timestamptz` (UTC); tanggal harian: `date` menurut WIB.
- Indeks komposit `(farm_id, flock_id, log_date)` pada tabel log harian.
- Ekstensi: `btree_gist` untuk exclusion constraint.

### 11.3 Aturan yang ditegakkan di database

Aturan bisnis kritis dijaga oleh constraint, bukan hanya kode aplikasi:

```sql
CREATE EXTENSION IF NOT EXISTS btree_gist;

-- BR-01: satu tempat pengeraman hanya satu induk pada satu waktu
ALTER TABLE hatch_batches
  ADD CONSTRAINT no_overlap_nest_box
  EXCLUDE USING gist (
    nest_box_id WITH =,
    daterange(started_on, COALESCE(closed_on, 'infinity')) WITH &&
  ) WHERE (status <> 'cancelled');

-- Satu induk tidak mengeram di dua tempat sekaligus
ALTER TABLE hatch_batches
  ADD CONSTRAINT no_overlap_hen
  EXCLUDE USING gist (
    bird_id WITH =,
    daterange(started_on, COALESCE(closed_on, 'infinity')) WITH &&
  ) WHERE (status <> 'cancelled');

-- BR-02: satu kandang hanya berisi satu induk (dan anakannya) pada satu waktu
ALTER TABLE coop_occupancies
  ADD CONSTRAINT no_overlap_coop
  EXCLUDE USING gist (coop_id WITH =, during WITH &&);

-- BR-10: qty selalu positif kecuali koreksi (adjust, boleh bertanda);
-- populasi tidak boleh negatif dijaga di service + tes; movement hanya ditambah (append-only)
ALTER TABLE flock_movements
  ADD CONSTRAINT qty_valid CHECK (qty <> 0 AND (qty > 0 OR kind = 'adjust'));
```

Pelanggaran constraint diterjemahkan oleh service menjadi pesan bahasa sederhana (lihat 6.3).

### 11.4 View populasi

```sql
CREATE VIEW flock_population AS
SELECT f.id AS flock_id,
       f.initial_count
         - COALESCE(SUM(m.qty) FILTER (WHERE m.kind IN ('dead','culled','lost','sold')), 0)
         + COALESCE(SUM(m.qty) FILTER (WHERE m.kind = 'adjust'), 0) AS alive
FROM flocks f
LEFT JOIN flock_movements m ON m.flock_id = f.id AND m.deleted_at IS NULL
GROUP BY f.id;
```

Kejadian `adjust` memakai `qty` bertanda (positif menambah, negatif mengurangi). Kejadian `moved` tidak mengubah populasi batch; efeknya tercatat di `coop_occupancies`. Hasil view harus selalu sama dengan rumus populasi di PRD dan diuji dengan tes unit.

## 12. Logika Domain

### 12.1 Perhitungan biaya batch

```ts
// modules/finance/service.ts (murni, mudah diuji)
export function batchCost(input: {
  motherAllocationIdr: number;
  feedCostIdr: number;
  medicineIdr: number;
  allocatedGeneralIdr: number;
  otherIdr: number;
}) {
  return input.motherAllocationIdr + input.feedCostIdr + input.medicineIdr
       + input.allocatedGeneralIdr + input.otherIdr;
}

export const hppPerBird = (totalCostIdr: number, sold: number, alive: number) =>
  sold + alive === 0 ? 0 : Math.round(totalCostIdr / (sold + alive));

export const provisionalProfit = (revenueIdr: number, hpp: number, soldCount: number) =>
  revenueIdr - hpp * soldCount;
```

Pembulatan: hasil bagi dibulatkan ke Rupiah terdekat; sisa pembulatan tidak dibawa. Semua rumus punya tes unit dengan contoh angka dari PRD.

### 12.2 Alokasi biaya umum (ekor-hari)

Untuk periode P, biaya umum B dibagi ke batch i sebesar `B × (ekor-hari_i ÷ total ekor-hari semua batch)`, dengan ekor-hari dihitung dari `daily_flock_summary.alive`. Alokasi dihitung ulang saat laporan dibuka (tidak disimpan) kecuali batch ditutup, saat itu hasil dibekukan.

### 12.3 Alokasi biaya indukan

Periode tetas = `started_on` sampai `closed_on` pada `hatch_batches`. Biaya indukan = pakan dan obat yang tertaut ke induk pada periode itu.

- **Per anakan (default):** seluruh biaya periode dibebankan ke batch hasil tetas sebagai biaya awal.
- **Per telur:** biaya per telur baik periode itu × telur yang dieram; sisa menjadi biaya umum.
- **Penetasan gagal:** seluruh biaya menjadi biaya umum.

### 12.4 Layak jual

```ts
export function isSellable(b: { ageDays: number; weightG: number; healthy: boolean },
                           cfg: { minAgeDays: number; minWeightG: number }) {
  return b.ageDays >= cfg.minAgeDays && b.weightG > cfg.minWeightG && b.healthy;
}
```

Evaluasi per ekor saat transaksi; evaluasi batch memakai bobot rata-rata sampling terakhir.

### 12.5 Estimasi tanggal mencapai 1 kg

ADG dari dua sampling terakhir (atau regresi linear bila ≥ 3 sampling). Tanggal = hari ini + (1000 − bobot terakhir) ÷ ADG. Dengan kurang dari 2 sampling: tampil "belum cukup data" dan target umur 90 hari dipakai sebagai perkiraan awal.

## 14. PWA dan Sinkronisasi Offline

**Cakupan offline (disengaja sederhana):** hanya catatan harian (pakan, minum, telur, kematian). Penjualan, biaya, dan pengaturan butuh internet.

**Antrean di IndexedDB:**

```ts
type QueuedOp = {
  clientOpId: string;          // UUID, juga disimpan di kolom client_op_id server (unik)
  type: 'feed' | 'water' | 'egg' | 'death';
  payload: unknown;            // sudah tervalidasi Zod
  createdAt: string;           // ISO
  attempts: number;
  status: 'pending' | 'sent' | 'failed';
};
```

**Alur:**

1. Pengguna menekan Simpan → operasi ditulis ke IndexedDB dan UI langsung berubah (optimistic).
2. Jika online, antrean dikirim ke `/api/sync` dalam satu permintaan; jika offline, menunggu event `online` atau Background Sync (bila didukung Chrome Android), ditambah percobaan saat aplikasi dibuka.
3. Server memproses tiap operasi dengan `client_op_id` unik: operasi yang sudah ada diabaikan (idempotent) dan dilaporkan sukses.
4. Respons memuat status per operasi; yang gagal validasi ditandai `failed` dengan alasan dan bisa diperbaiki pengguna.

**Konflik:** catatan harian di-upsert menurut kunci alami (`flock_id/bird_id` + `log_date` + jenis), kejadian pergerakan hanya ditambah. Edit terakhir menang (last write wins), karena hanya ada satu pengguna.

**Cache aset:** Serwist melakukan precache shell aplikasi dan font; data dibaca dari TanStack Query dengan persistensi lokal sehingga Beranda bisa tampil terakhir diketahui saat offline.

## 15. Mesin Alert dan Pengingat

- Pekerjaan terjadwal di pg-boss: evaluasi harian pukul 06.00 WIB, evaluasi "catatan belum diisi" pukul 18.00 WIB, dan evaluasi seketika setelah tulis tertentu (kematian, hitung ulang).
- Setiap aturan adalah fungsi murni `(state) → Alert[]` di `modules/monitoring/rules/`, dengan `dedupe_key` (`rule:entity:periode`) agar alert tidak menggandakan.
- Daftar aturan dan ambang default tercantum di PRD 8.10; ambang tersimpan di `farms.settings`.
- Alert berstatus `open → read → resolved`; alert otomatis `resolved` bila kondisi hilang (misalnya vaksin sudah dicatat).
- Tanpa web push pada tahap awal; titik notifikasi di UI membaca `alerts.status = open`.

## 16. Desain Layer AI

```ts
// modules/ai/provider.ts
export interface LLMProvider {
  parseLog(text: string, ctx: LogContext): Promise<ParsedLog>;       // model ringan
  chat(messages: Msg[], tools: ToolDef[]): AsyncIterable<ChatEvent>; // model analisis
  summarize(stats: WeeklyStats): Promise<string>;
  assessSymptom(input: SymptomInput): Promise<SymptomAssessment>;
}
```

- Model dipilih lewat environment variable (`AI_MODEL_LIGHT`, `AI_MODEL_ANALYSIS`), sehingga ganti model atau vendor tidak mengubah fitur.
- **Tool read-only** untuk asisten (nama contoh): `get_population`, `get_batch_cost_summary`, `get_feed_cost_trend`, `get_sales_summary`, `get_cashflow`, `get_hatch_status`, `get_weight_curve`, `get_open_alerts`. Setiap tool memanggil service modul domain, tidak ada akses SQL bebas.
- **Catat bahasa natural:** keluaran model dipaksa ke skema Zod (`ParsedLog`), divalidasi, lalu dikirim ke klien sebagai pratinjau. Penyimpanan baru terjadi lewat action biasa setelah pengguna menekan Simpan, sehingga AI tidak punya jalur tulis langsung.
- **Aturan merah kesehatan:** pemeriksa rule-based berjalan **sebelum dan di luar** LLM (kematian mendadak dalam jumlah banyak, gejala menular); bila terpicu, antarmuka menampilkan arahan ke dokter hewan tanpa menunggu model.
- **Insight mingguan:** statistik dihitung dulu (rata-rata bergerak, z-score) oleh kode; LLM hanya menarasikan angka yang sudah ada.
- **Kontrol biaya:** batas permintaan per hari, cache jawaban untuk pertanyaan yang sama pada data yang sama, pencatatan token dan biaya di `ai_messages`.
- **Privasi:** hanya data yang relevan dikirim; nomor kontak pembeli tidak dikirim.
- **Evaluasi:** kumpulan kasus uji Bahasa Indonesia di `tests/ai-eval/` (pencatatan, pertanyaan data, gejala) dijalankan sebelum rilis; target akurasi disepakati dengan klien.
- **Degradasi:** semua panggilan AI memiliki timeout dan penanganan gagal; kegagalan tidak boleh memblokir fitur non-AI.

## 17. Keamanan

- HTTPS di seluruh jalur; HSTS; cookie sesi `HttpOnly`, `Secure`, `SameSite=Lax`.
- Hash password argon2id (atau bcrypt); rate limit login dan endpoint AI.
- Validasi Zod di semua input; kueri berparameter lewat ORM; `farm_id` selalu dari sesi.
- Unggahan foto: batasi tipe dan ukuran, simpan di object storage dengan nama acak, tautan bertanda tangan berumur pendek.
- Audit log untuk perubahan keuangan, penutupan atau pembukaan batch, dan penghapusan.
- Backup harian terenkripsi ke object storage terpisah (retensi ≥ 30 hari) dan uji restore berkala.
- Rahasia di environment variable, tidak di repositori.
